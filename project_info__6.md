# Rack Calculation — гидравлическая схема агрегата

> Отчёт сохранён в `project_info__5.md`. Текущая сессия — **Explore Mode**: писать код и запускать команды я здесь не могу. Последняя правка схемы (по вашим пяти замечаниям) была **уже выполнена и проверена** до переключения режима; незакрытые шаги перечислены в конце и требуют **Act Mode**.

## Резюме

`Rack Calculation` — веб-приложение для подбора компрессорно-ресиверных агрегатов: полиномы AHRI/EN12900, расчёт трубопроводов, автоподбор опций, КП в EUR без НДС и производственная спецификация. Стек: Node.js + Express + `node:sqlite` + EJS + Telegram-бот, сборщика нет.

Ключевой принцип схемы: **чертёж не хранится и не рисуется вручную** — он собирается из спецификации расчёта (`result.bom`) при каждом рендере. Поэтому в КП, сохранённых до правки, новых обязательных позиций (например, Rotalock после ресивера) не будет — спецификация там старая.

## Что сделано в последней правке (5 замечаний, проверено 14/14)

1. **Линии нагнетания и слива разведены без пересечения.** Подъём нагнетания — `RISER_X = 1390`; опуск от конденсатора — `LIQUID.condenserDropX = 1300`, причём слив идёт **из нижнего днища** конденсатора (`M 1300 255 V 370 H 420`), а не сбоку. Конденсатор: `{ cx: 1250, cy: 190, w: 320, h: 130 }`. Отсутствие пересечений проверено перебором отрезков «нагнетание × жидкость».
2. **Предохранительный клапан подключён к ресиверу.** Причина «висел в воздухе»: маска знака `maskC(60, 84)` заходила на 42 ед. **ниже** точки врезки (при `scale 0.5` — 21 px) и стирала штуцер. Заменено на `maskRect(-22, -80, 44, 80)`; штуцер `M 1000 370 V 280` виден целиком, клапан на `safetyY = 280`.
3. **Запорный Rotalock сразу после ресивера.** Добавлена позиция `receiver_outlet_valve` («Запорный вентиль Rotalock после линейного ресивера», марка `FP-RV-038 SAE`, обязательная), знак — `rotalock_valve` на `outletValveX = 860`. Порядок по потоку (справа налево): конденсатор → NRV 1240 → вход NRD 1200 → вентиль входа 1150 → ресивер 1000 → **Rotalock 860** → фильтр 780 → глазок 680 → соленоид 580 → кран 500.
4. **Размеры линий на свободных местах:** нагнетание `(480, HEADER_Y − 20)`, жидкость `(560, LIQUID_Y + 28)`, всасывание `(SUCTION_X − 28, 720)` c поворотом −90 (слева от вертикали, где нет приборов). Проверка сравнивает координаты подписей со всеми знаками.
5. **Зазор под обозначением регулятора масла +10 % высоты шрифта** (18 px → +1,8 px): `tagDy` знака `level_regulator` 40 → **42**.

Проверочный скрипт вернул: «линия нагнетания и линия слива не пересекаются», «вырез клапана не съедает штуцер (маска y=−80 h=80)», «запорный вентиль сразу после ресивера — V5@860», «между ресивером и вентилем нет других позиций», «зазор 42, зазор 42» — **все 14 проверок зелёные**. Свежий КП для визуального контроля: **KP-2026-0031**.

## Архитектура

Слоистая схема «thin route → service → view»: `server.js` (Express, сессии, `syncOptions` при старте) → `routes/*` (без бизнес-логики) → `services/*` (вся расчётная логика, включая `schematic.js`) → `views/*` (EJS).

```
services/schematic.js        ★ геометрия, SYMBOLS, buildWires, buildSchematic
views/partials/schematic.ejs ★ рендер SVG + легенда «обозначение/наименование/марка/кол-во»
db/optionDefinitions.js      ★ OPTIONS + OPTION_ARTICLES (единый источник истины)
db/database.js                 схема БД + syncOptions (правки применяются при старте!)
services/{calc,options,piping,vibration,selection,refrigerants,pricing,inch}.js
public/css/schematic.css       стили схемы
```

## Поток данных

1. `POST /calc` (`routes/calc.js`).
2. `services/calc.js`: цикл → `selection` → `piping` → `vibration` → `options` → результат с `bom`.
3. `buildSchematic(result)` → модель `{ width, height, wires[], arrows[], blocks[], legend[], otherItems[], lineLabels[], pipes{}, notes[] }`.
4. `partials/schematic.ejs` рисует SVG; `inch()` даёт запись вида `1 5/8"`.
5. Тот же `buildSchematic` используется для карточки КП, печати и производственного задания.

## Ключевые абстракции

- **`buildSchematic(result)`** — `services/schematic.js`; единственный экспорт модуля; чистый вычислитель, ничего не кэширует и не пишет в БД; возвращает `null` на пустой спецификации.
- **`SYMBOLS`** — библиотека знаков в **локальных** координатах вокруг точки врезки (0,0). Поля: `{ scale?, mask, maskless?, tagInside?, tagDx, tagDy, tagAnchor?, shapes[] }`. `mask` — **белый вырез**, стирающий трубу под знаком; он масштабируется вместе со знаком (`scale(...)` внутри `<g>`).
- **`layoutOf(compressorXs)`** — инвариант `oilHeaderX = max(1100, правый регулятор + 135)`: маслоотделитель и масляный ресивер всегда правее врезок регуляторов уровня.
- **`stubLayout(fromY, toY, items)`** — раскладка ветки КМ (вентиль → виброгаситель → обратный клапан); идёт с конца списка, т.к. список упорядочен от компрессора к магистрали (поток снизу вверх).
- **`OPTIONS` / `OPTION_ARTICLES`** — справочник опций и заводские обозначения позиций, отсутствующих в каталоге компонентов.
- **`schematic.ejs`** — контракт порядка отрисовки: `pipes → arrows → units → line-labels`; знаки стирают масками трубы, но могут «отрезать» друг друга.

## Неочевидные поведения (самое важное)

- **Маски — главный источник визуальных дефектов.** Маска не должна пересекать точку врезки снизу у знаков на коротких штуцерах (именно так «отрывался» предохранительный клапан).
- **Стирание чужих знаков масками.** Порядок блоков: компрессоры → масляная линия → подъём нагнетания → жидкостная линия → предохранительный клапан → навесное на ресивере → всасывание → приборы → байпас → конденсатор. Конденсатор рисуется последним и «съедает» всё под собой — это ожидаемо.
- **Нумерация обозначений зависит от порядка обхода.** `tagFor()` присваивает номер при первом обращении; повторные знаки одной позиции (виброгасители всех КМ, компрессоры одной модели) получают **одно** обозначение — отсюда номера `V1, VA1, V2, V3, OML1`.
- **Одна опция — много позиций.** Виброгасители — одна опция `vibration`, но две позиции; линия определяется по `result.vibration[line].bomItems[0].article` с фолбэком на название («всасыван» / «нагнетания»). Старые коды `vibration_suction` / `vibration_discharge` поддерживаются для старых КП.
- **`COMP.limit = 4`** — рисуются первые 4 компрессора, остальные уходят в `notes`.
- **Конденсатор — внешний элемент** (`placeExternal`): в легенду не попадает, даёт примечание `K1 — конденсатор (внешний)`.
- **Испаритель и ТРВ исключены** по требованию заказчика: линии заканчиваются патрубками, названия «Жидкостная линия», «Всасывающая линия», «вывод к/от испарителя» убраны, осталась только подпись «Нагнетание» с размером.
- **Третий штуцер ресивера** — порт предохранительного клапана; NRD входит между NRV и вентилем входа; `winter_nrv_drain` переведён в «по выбору», т.к. основной NRV на сливе — штатная позиция `liquid_nrv`.
- **Графа «Марка»:** каталог компонентов → `OPTION_ARTICLES` → `opt.code.toUpperCase()`. Заводские обозначения из ЗП24.2158: `FP-OF-038s`, `FP-RV-014 SAE`, `FP-RV-038 SAE`, `FP-ERL4`, `FP-SV-038`, `6210/2`, `NRD 12s`, `KP15 авт.`, `PB11 / PB21`.
- **Сервер надо перезапускать** после правки `db/optionDefinitions.js` — БД обновляется через `syncOptions` при старте.
