# Алгоритм расчёта холодильного цикла

Документ фиксирует **фактический алгоритм** расчёта холодильного цикла в текущей
версии приложения (as-built), приводит числовой пример из работающего приложения,
перечисляет найденные ошибки с доказательствами и даёт **целевой алгоритм** для
внесения корректировок.

Проверочный прогон: `R404a`, `tEvap = −10 °C`, `tCond = 45 °C`, `dTsh = 10 K`,
`dTsc = 0 K`, компрессор Copeland `ZB114KQE` × 2.

---

## 1. Где считается цикл

| Шаг | Файл | Функция / строка | Что делает |
|-----|------|------------------|------------|
| 1 | `services/calc.js` | `calculateCore()`, шаг 1 | `selection.evaluateSelection()` — Q, N, I, ṁ из полиномов AHRI |
| 2 | `services/calc.js` | `calculateCore()`, шаг 2 | `piping.calcPiping()` — диаметры; внутри вызывает `lineDensity()` |
| 3 | `services/piping.js` | `lineDensity()` | берёт плотности из `refrigerants` |
| 4 | `services/selection.js` | `compressorPerformance()` | если нет `poly_mass` — ṁ оценивается по энтальпиям |
| 5 | `services/calc.js` | `calculateCore()`, шаг **9** | `refr.cyclePoints()` — «точки цикла» **только для показа** |
| 6 | `views/calc.ejs` | таблица «Свойства хладагента — точки цикла» | вывод 4 точек |

**Ключевая архитектурная особенность:** блок цикла считается **последним**
(шаг 9) и используется **только для отображения**. Трубопроводы (шаг 2) и
виброгасители (шаг 3) считают плотности своими вызовами тех же функций, ṁ берут
из полиномов. Единого объекта «состояние цикла», который потребляли бы все
потребители, в системе нет — отсюда рассогласование блоков на одном экране:
COP из полиномов компрессоров (KPI-плитка) и COP, который следует из показанных
энтальпий, различаются в 5 раз (см. § 5).

## 2. Входные данные

Из формы (`views/calc.ejs`, шаг 01):

- `refrigerant` — R404a | R507a | R410a | R32 | R449b;
- `tEvap` — температура кипения, °C;
- `tCond` — температура конденсации, °C;
- `dTsh` — перегрев на всасывании, К (по умолчанию 10);
- `dTsc` — переохлаждение жидкости, К (по умолчанию 0);
- `requiredKw` — требуемая холодопроизводительность, кВт.

Давлений, перепадов давления, температур в линиях и точки росы/пузырька
пользователь задать не может — они не являются входами модели.

## 3. Полный алгоритм as-built

### 3.1. Интерполяция свойств

```
T_GRID = [-50, -40, -30, -20, -10, 0, 10, 20, 30, 40, 50, 60]  // °C

interp(table, t):
  t <= -50        → table[0]
  t >=  60        → table[последний]
  иначе           → линейная интерполяция между соседними узлами
```

Экстраполяции нет: ниже −50 °C и выше 60 °C значения «прилипают» к крайним
узлам (для R404a при `tCond = 45 °C` это ещё интерполяция, а вот при `tCond = 55 °C`
уже нет — 36.0 бар вместо реальных ~40).

### 3.2. Давление насыщения

```
p_sat(code, t) = interp(psat, t),  бар абсолютное
```

`psat` — таблица из 12 значений (узлы `T_GRID`). Для R404a:
`… 6.18 (−10 °C), 8.90 (0 °C), … 28.4 (40 °C), 36.0 (50 °C) …`.

### 3.3. Энтальпии

```
h_f(t)   = h_f0 + cp_l · t                         // жидкость
h_g(t)   = h_f0 + cp_l · t + (latent0 − 0.35·t)    // насыщенный пар
h_sh(tSat, tSup) = h_g(tSat) + cp_v · max(tSup − tSat, 0)   // перегретый пар
```

Константы по хладагентам (`h_f0 = 200`, `latent0 = 183…330`, `cp_v ≈ 0.88`,
`cp_l ≈ 1.45`). Для R404a: `h_f0 = 200`, `latent0 = 185`, `cp_v = 0.88`, `cp_l = 1.45`.

### 3.4. Температура нагнетания

```
pe = p_sat(tEvap);  pc = p_sat(tCond);  r = max(pc/pe, 1.01)
T1 = tEvap + 273.15
dT = T1 · (r^((k−1)/k) − 1) · (1/η_is − 1) · cp_v        // k = k_ex, η_is = 0.75
tDisch = tCond + max(dT, 10)
```

### 3.5. Плотности

```
ρ_вс(ид.газ)  = (p_sat(tEvap) · 1e5 · 0.92) / ((8314 / M) · (tEvap + dTsh + 273.15))
ρ_наг(ид.газ) = (p_sat(tCond) · 1e5 · 0.95) / ((8314 / M) · (tDisch + 273.15))
ρ_ж(t)        = interp(rho_l, t)
ρ_пар.нас(t)  = interp(rho_v, t)
```

### 3.6. Точки цикла (`cyclePoints`)

```
h1 = h_sh(tEvap, tEvap + dTsh)                                  // всасывание
h2 = h1 + (h_sh(tCond, tDisch) − h_g(tCond))  =  h1 + cp_v·(tDisch − tCond)   // конец сжатия
h3 = h_f(tCond − dTsc)                                          // переохлаждённая жидкость
h4 = h3                                                         // дросселирование

suction   = { t: tEvap + dTsh, p: p_sat(tEvap), ρ: ρ_вс,   h: h1 }
discharge = { t: tDisch,       p: p_sat(tCond), ρ: ρ_наг,  h: h2 }
liquid    = { t: tCond − dTsc, p: p_sat(tCond), ρ: ρ_ж(tCond − dTsc), h: h3 }
throttle  = { t: tEvap,        p: p_sat(tEvap), ρ: ρ_ж(tEvap),        h: h4 }
```

### 3.7. Массовый расход

```
if (есть poly_mass)  ṁ = poly_mass(tEvap, tCond) / multiplier
else                 q0 = h_sh(tEvap, tEvap + 10) − h_f(tCond)     // dTsh = 10 ЖЁСТКО
                     ṁ  = Q · 3600 / q0
```

`dTsh = 10` и `dTsc = 0` в этой ветке заданы литералами и **не берутся из формы**.

### 3.8. Диаметры трубопроводов

```
ρ линии = ρ_вс (всасывание) | ρ_наг (нагнетание) | ρ_ж(tCond − dTsc) (жидкость)
V̇ = (ṁ / 3600) / ρ,  м³/с
A = π · ((OD − 2·стенка)/1000)² / 4,  м²         // таблица pipe_sizes
v = V̇ / A
рекомендация: минимальный размер с v ≤ v_рек, где v_рек = 12 / 12 / 1.2 м/с
диапазон: всасывание 6…15, нагнетание 6…18, жидкость 0.4…1.5 м/с
```

### 3.9. Что показывается пользователю

- KPI-плитки: Q, N, COP = Q/N, ṁ — **из полиномов компрессоров**;
- «Характеристики агрегата»: Q, N, тепло = Q + N, COP, ṁ, ток;
- «Свойства хладагента — точки цикла»: t, P, ρ, h по 4 точкам — **из § 3.6**;
- «Трубопроводы»: ṁ, V̇, Ø, труба, скорость, проверка — **из § 3.8**.

## 6. Найденные ошибки

### E1. Работа сжатия не связана с отношением давлений (главная ошибка)

`h2 = h1 + cp_v · (tDisch − tCond)` (§ 3.6) — это **не энергетический баланс**.
Удельная работа получилась `w = cp_v · (61.1 − 45) = 14.2 кДж/кг`, хотя при
`p_cond / p_evap = 32.2 / 6.18 = 5.2` для R404a работа сжатия составляет
**50…75 кДж/кг** (у нас ṁ = 1320 кг/ч и N = 26.46 кВт → `w = N·3600/ṁ = 72.2 кДж/кг`).

**Следствие:** COP, который следует из показанных энтальпий (`117.55 / 14.21 = 8.27`),
и COP из полиномов компрессоров (`1.629`) расходятся в 5 раз. Обе цифры видны
инженеру на одном экране.

**Правильно:** энтальпия конца сжатия берётся из энергобаланса компрессора:

```
w  = N · 3600 / ṁ                      // из полинома мощности, кДж/кг
h2 = h1 + w
t2 = t(ρ_наг, p_cond)                  // обратная функция свойств перегретого пара
```

Это автоматически связывает блок цикла с полиномами и даёт настоящую температуру
нагнетания. Если нужен расчёт без полинома мощности — считать через изоэнтропу:

```
s2 = s1 → h2s = h(p_cond, s1);  h2 = h1 + (h2s − h1) / η_is;  t2 = t(p_cond, h2)
```

### E2. Формула температуры нагнетания физически некорректна

```
dT = T1 · (r^((k−1)/k) − 1) · (1/η − 1) · cp_v
tDisch = tCond + max(dT, 10)
```

1. Множитель `cp_v` (кДж/(кг·К)) делает результат **не температурой**, а
   произведением температуры на теплоёмкость — размерность не сходится.
2. Изоэнтропный перегрев считается как `T2s = T1·r^((k−1)/k)` (это корректно),
   но затем к нему применяется `(1/η − 1)` вместо `(T2s − T1)/η`.
3. `tDisch` привязана к `tCond` (`tCond + …`) с полом `max(…, 10)`, поэтому при
   любом режиме результат лежит в узкой полосе: в примере 61.1 °C, при более
   широком отношении давлений всё равно упрётся в пол `tCond + 10`.
   Реальная температура нагнетания поршневого/спирального агрегата на R404a
   при −10/45 составляет 70…90 °C.

**Правильно:** `T2 = T1 + (T2s − T1) / η_is` при постоянной `cp` **или** (надёжнее)
через энтальпию из E1. Никаких привязок к `tCond` и никаких «полов».

**Следствия:** `ρ_наг` (завышена), `V̇` нагнетания (занижен), скорость и диаметр
нагнетания (занижены).

### E3. Плотность всасываемого пара завышена ~40 % — физически невозможно

```
ρ_вс = (p_sat(tEvap)·1e5 · 0.92) / (R·(tEvap + dTsh + 273.15))
```

Идеальный газ с постоянной поправкой `Z = 0.92`. Расчёт даёт
**ρ_вс(−10 °C, перегрев 10 K) = 24.44 кг/м³**, тогда как табличная плотность
**насыщенного** пара при −10 °C — **17.4 кг/м³**. Перегрев при том же давлении
обязан **уменьшить** плотность (при 6.18 бар и +10 K: ≈ 16.8 кг/м³), а не
увеличить её на 40 %.

Причина: R404a при −10 °C далёк от идеального газа (`Z ≈ 0.63`), а не 0.92.
Ошибка ≈ **+45 %**, причём в опасную сторону.

**Следствия:** `V̇` всасывания занижен (54.0 м³/ч вместо ≈ 78 м³/ч), скорость
занижена (7.65 м/с вместо ≈ 11 м/с), диаметр всасывающей линии занижен —
на пределе диапазона 6…15 м/с.

**Правильно:** плотность перегретого пара брать из таблиц перегретого пара или
считать по уравнению состояния с реальным `Z(p, T)` из свойств, а не константой:
`ρ = p / (Z(p,T) · R · T)`, `Z` — из таблиц (или CoolProp/REFPROP).

### E4. Давление всасывания — это давление кипения, перепады не учтены

```
p_suction = p_sat(tEvap)
```

Показывается давление **в испарителе**, а не на всасывающем патрубке
компрессора. Перепад давления во всасывающей линии (и в её арматуре) не
учитывается, хотя в модуле уже есть готовая функция пересчёта `dTfromdP(p, Δp)`,
которая **не вызывается нигде**.

**Правильно:**

```
p_suction = p_evap − Δp_всас        // Δp задаётся нормативом или подбирается
t_suction = tEvap + ΔT_линия + dTsh // t1 — уже с нагревом в линии
```

Аналогично для нагнетания (`p_discharge = p_cond + Δp_нагн`) и жидкости
(`p_liquid = p_cond − Δp_жидк`).

### E5. Абсолютное/избыточное давление и глайд не различаются

- Все давления — **бар абсолютное** (6.18 и 32.20), но нигде это не помечено.
  На манометре инженер увидит 5.17 и 31.19 бар изб. — расхождение принимается
  за ошибку расчёта.
- `glide` (0.7 K для R404a, 4.5 K для R449b) в расчёте не используется вообще:
  для зеотропных смесей температура кипения/конденсации — это диапазон
  (точка росы / точка пузырька), а `p_sat(t)` в таблице — одно значение.

**Правильно:** хранить и показывать `p_abs` и `p_gauge`, а для смесей — считать
`t_bubble`/`t_dew` и `p_sat` на них.

### E6. Энтальпии — линейная модель, а не таблицы

```
h_f = 200 + 1.45·t                               // постоянная теплоёмкость жидкости
h_g = h_f + (185 − 0.35·t)                       // линейная аппроксимация теплоты парообразования
h_sh = h_g(tSat) + 0.88·(tSup − tSat)            // постоянная cp перегретого пара
```

Точка отсчёта выбрана корректно (`h = 200 кДж/кг` для жидкости при 0 °C — как в
IIR/ASHRAE), но температурные зависимости линейные:

- теплота парообразования у R404a падает с температурой существенно круче,
  чем `0.35 кДж/(кг·K)`, поэтому `h_g` на краях диапазона уходит от таблиц на
  десятки кДж/кг;
- `cp_v` перегретого пара зависит от давления и температуры (у R404a на
  всасывании ≈ 0.9…1.0, на нагнетании ≈ 1.1…1.3 кДж/(кг·K)), а взята константой
  0.88 — то есть теплоёмкость на линии нагнетания **занижена вдвое**.

**Правильно:** табличные `h_f`, `h_g`, `s` по температуре (и по давлению для
перегретого пара) с линейной/кубической интерполяцией, либо подключение
CoolProp/REFPROP.

### E7. Точка дросселирования показана как жидкость

`throttle = { t: tEvap, ρ: ρ_ж(tEvap), h: h3 }` — но после ТРВ хладагент
**двухфазный**. При показанных же значениях степень сухости:

```
x = (h4 − h_f(tEvap)) / (h_g(tEvap) − h_f(tEvap))
  = (265.25 − 185.5) / (374.0 − 185.5) = 0.42
ρ_см = 1 / (x/ρ_пар + (1−x)/ρ_ж) = 1 / (0.42/17.4 + 0.58/848) ≈ 40 кг/м³
```

То есть на месте 848 кг/м³ должно быть ≈ 40 кг/м³ — расхождение в 20 раз.

### E8. Массовый расход в резервной ветке считается по «зашитым» числам

`services/selection.js`:

```
q0 = h_sh(tEvap, tEvap + 10) − h_f(tCond)     // dTsh = 10 и dTsc = 0 — литералы
```

Если в каталоге нет `poly_mass`, ṁ считается с перегревом 10 K и без
переохлаждения независимо от того, что ввёл инженер. При `dTsh = 5` или
`dTsc = 8` массовый расход (а с ним скорости и диаметры) будет неверным.
Правильно: `q0 = h1 − h3` из § 3.6, то есть из уже рассчитанного цикла.

### E9. Цикл не является единым источником истины

Блок цикла считается **после** трубопроводов и виброгасителей и ни на что не
влияет. Итог: три разных источника чисел на одном экране.

| Величина | Откуда берётся | Согласованность |
|----------|----------------|-----------------|
| Q, N, COP, ṁ | полиномы AHRI | между собой согласованы |
| h1…h4, t, P, ρ | `cyclePoints()` | **не согласованы с Q/N/ṁ** |
| диаметры, скорости | `lineDensity()` + ṁ из полиномов | используют «свои» плотности |

**Правильно:** сначала строится состояние цикла (единый объект), затем из него
берутся и ṁ, и плотности, и диаметры, и отображаемые точки; полиномы дают Q и N,
которые **проверяются** на согласованность с циклом (см. предупреждения в § 7).

### E10. Нет предупреждений о рассогласовании и о выходе за диапазон

- COP по циклу и COP по полиномам не сравниваются — расхождение в 5 раз
  пользователю не показывается.
- При `tCond`/`tEvap` за пределами `T_GRID` интерполяция «прилипает» к крайним
  узлам молча (`t <= -50 → table[0]`, `t >= 60 → table[last]`) — ни `warnings`,
  ни пометки в интерфейсе.
- Линейная модель не проверяется ни на один физический инвариант
  (`ρ_перегретого < ρ_насыщенного` — именно тот инвариант, который нарушен в E3).

### E11. Значения таблиц требуют сверки (проверить по ASHRAE/CoolProp)

`ρ_ж(40 °C) = 682`, `ρ_ж(50 °C) = 635` кг/м³ для R404a (критическая температура
72 °C) выглядят заниженными; `ρ_пар(−10 °C) = 17.4` — правдоподобно, но должно
быть согласовано с `p_sat` по уравнению состояния. Перед правкой кода эти
таблицы нужно сверить с табличным источником — они дают систематическую ошибку
во всех плотностях сразу.

## 7. Целевой алгоритм

Ниже — алгоритм, который предлагается реализовать. Он сохраняет текущую
структуру модулей (`services/refrigerants.js` + `services/cycle.js`),
но вводит единый объект состояния цикла.

### Шаг 0. Свойства (замена § 3.1–3.5)

Источник свойств должен уметь:

```
p_sat(code, t)            → бар абс. (или p_sat_bubble / p_sat_dew для смесей)
T_sat(code, p)            → обратная функция
h_f(code, t)              → кДж/кг (жидкость на линии насыщения)
h_g(code, t)              → кДж/кг (пар на линии насыщения)
h_ph(code, p, t)          → кДж/кг (перегретый пар)
t_ph(code, p, h)          → обратная функция (температура по p и h)
rho_ph(code, p, t)        → кг/м³ (перегретый пар, реальный газ)
rho_f(code, t)            → кг/м³ (жидкость)
s_ph(code, p, t)          → кДж/(кг·K) (для изоэнтропы)
```

Допустимы два варианта: (а) таблицы на сетке `t × p` с интерполяцией;
(б) подключение CoolProp (для Node.js — через внешний процесс/FFI) с кэшем.
Вариант (а) дешевле по внедрению и достаточен для инженерного расчёта при
шаге таблицы 1 K и 0.5 бар.

### Шаг 1. Границы цикла

Вход: `refrigerant`, `tEvap`, `tCond`, `dTsh`, `dTsc`, `Q` (или `requiredKw`).

```
p_evap  = p_sat(code, tEvap)                 // низкая сторона
p_cond  = p_sat(code, tCond)                 // высокая сторона
Δp_всас = норматив или подбор (например 0.15 бар на 10 м линии + арматура)
Δp_нагн = норматив
Δp_жидк = норматив
p1 = p_evap − Δp_всас                        // давление на всасывающем патрубке
p2 = p_cond + Δp_нагн                        // давление на нагнетательном патрубке
p3 = p_cond − Δp_жидк                        // давление жидкости перед ТРВ
```

### Шаг 2. Четыре точки цикла

```
t1 = tEvap + dTsh (+ ΔT_нагрев в линии, если учитывается)
h1 = h_ph(code, p1, t1)
ρ1 = rho_ph(code, p1, t1)

t3 = tCond − dTsc
h3 = h_f(code, t3)
ρ3 = rho_f(code, t3)

h4 = h3                                      // дросселирование: h = const
x4 = (h4 − h_f(code, tEvap)) / (h_g(code, tEvap) − h_f(code, tEvap))
ρ4 = 1 / (x4/rho_ph(code, p_evap, tEvap) + (1−x4)/rho_f(code, tEvap))
```

### Шаг 3. Согласование с компрессором

Q и N берутся из полиномов AHRI (`selection.js`). Далее:

```
q0 = h1 − h4                                 // удельная холодопроизводительность
ṁ  = Q · 3600 / q0                           // кг/ч — ЕДИНЫЙ расход для всех линий
w  = N · 3600 / ṁ                            // удельная работа, кДж/кг
h2 = h1 + w
t2 = t_ph(code, p2, h2)                      // температура нагнетания
ρ2 = rho_ph(code, p2, t2)
η_is = (h2s − h1) / w,  где h2s = h(p2, s1)  // фактический изоэнтропный КПД (для контроля)
COP = q0 / w
```

Проверки (в `warnings`):

- `COP` по циклу и `COP = Q/N` по полиномам должны совпадать по построению —
  если не совпадают, значит неверны таблицы свойств или `ṁ`;
- `t2` вне 50…130 °C — предупреждение;
- `η_is` вне 0.5…0.85 — предупреждение (признак ошибки в полиноме мощности);
- `x4` вне 0.05…0.3 — предупреждение (ненормальное переохлаждение/перегрев);
- `tEvap`/`tCond` вне табличной сетки — предупреждение вместо молчаливой
  экстраполяции.

### Шаг 4. Потребители (единый объект `cycle`)

```
cycle = {
  evap:   { t, p, p_gauge, h, rho, x },
  suction:{ t, p, p_gauge, h, rho },
  discharge:{ t, p, p_gauge, h, rho },
  liquid: { t, p, p_gauge, h, rho },
  throttle:{ t, p, p_gauge, h, rho, x },
  q0, w, massFlow_kgh, cop, eta_is, glide, warnings[]
}
```

- `piping.calcPiping()` берёт `ρ` **из `cycle`** (не пересчитывает своими
  формулами) и `ṁ = cycle.massFlow_kgh`;
- `vibration.planAll()` — то же;
- `selection` — при отсутствии `poly_mass` берёт `q0 = h1 − h4` из `cycle`;
- `views/calc.ejs` — печатает `p_abs` и `p_gauge` рядом, добавляет строку
  дросселирования со степенью сухости `x`.

### Шаг 5. Диаметры (без изменений по идее, но на новых плотностях)

```
V̇ = (ṁ / 3600) / ρ_линии;  v = V̇ / A;  выбрать Ø с v ≤ v_рек
```

Дополнительно рекомендуется подбирать диаметр **по перепаду давления**
(`Δp_линии` из § Шага 1) и проверять согласованность: фактический `Δp` при
выбранном Ø должен совпасть с принятым в расчёте цикла — тогда `p1`, `p2`, `p3`
и диаметры взаимно согласованы.
